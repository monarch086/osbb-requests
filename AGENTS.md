# Правила роботи з проєктом

Цей файл поширюється на весь репозиторій. Спілкування з користувачем і тексти інтерфейсу — українською; назви типів, методів і комітів — англійською.

## Контекст і структура

- Продукт: Telegram-бот ОСББ та вебпанель ЖК «Зелений острів 2»: чотири будинки 4Б, 4В, 4Г та 4Д по 25 поверхів. У текстах рівня всього ЖК використовуйте «комплекс»; «будинок» — лише для конкретного будинку.
- `src/OsbbRequests.Bot` — webhook, обробка команд із SQS, реєстрація мешканців і Telegram-клієнт.
- `src/OsbbRequests.AdminApi` — Cognito-автентифікація, адміністративні операції та доступ до DynamoDB.
- `src/OsbbRequests.Shared` — спільні моделі й допоміжний код.
- `src/Frontend` — Angular SPA: авторизація, заявки, мешканці, адміністратори та діалоги.
- `tests/OsbbRequests.Bot.Tests` — тести .NET, зокрема API та інфраструктури; `tests/admin` — Python-тести операторських скриптів.
- `serverless.yml` — AWS-інфраструктура; `scripts` — пакування, деплой фронтенду та операторські міграції.
- Перед зміною поведінки прочитайте відповідні розділи `README.md`, `docs/architecture.md` і `docs/requirements.md`. Вимоги описують також майбутні функції; не вважайте їх уже реалізованими.

## Інструменти й залежності

- Node.js 24 визначено в `.nvmrc`; версію .NET SDK беріть із `global.json`.
- Backend: .NET 10, AWS Lambda Linux ARM64, Serverless Framework 4, DynamoDB, SQS FIFO, SSM.
- Frontend: Angular 21, template-driven forms, Bootstrap 5 та `@ng-select/ng-select` сумісної з Angular мажорної версії.
- Використовуйте `npm ci` для відтворюваного встановлення. Оновлення залежностей супроводжуйте змінами відповідного `package-lock.json` або `packages.lock.json`.
- Не додавайте до Git секрети, локальні credentials, `node_modules`, кеші, `dist`, `bin`, `obj` чи `artifacts`.

## Frontend

- Зберігайте компоненти невеликими й розділяйте їх за відповідальністю. `AppComponent` відповідає за оболонку та авторизацію; `WorkspaceComponent` координує стан і запити API; дочірні компоненти отримують дані й передають дії через inputs/outputs.
- Для випадаючих списків використовуйте **ng-select**, для оформлення — **Bootstrap**: сітку, форми, кнопки, картки, навігацію, повідомлення та модальні діалоги.
- Власний SCSS залишайте для оформлення, якого немає в Bootstrap, і інтеграції ng-select. Не відновлюйте загальні стилі `button`/`input`, що перекривають стилі бібліотек.
- Bootstrap CSS і тема ng-select підключені локально через `angular.json`; не додавайте CDN або Bootstrap JavaScript для поведінки, якою керує Angular.
- Пов'язуйте поля з видимими підписами. Для ng-select використовуйте `labelForId`; перевіряйте пошук, вибір клавіатурою, очищення необов'язкових значень і відображення списків поверх модальних діалогів.
- Зберігайте завантаження, помилки, блокування повторних дій і захист від застарілих асинхронних відповідей під час виходу або зміни користувача.
- Конфігурація `src/assets/app-config.json` містить лише публічні API/Cognito ID; у репозиторії зберігається порожній шаблон. Авторизаційні сесії використовують sessionStorage.
- Дотримуйтеся ESLint, Angular accessibility rules, Stylelint і Prettier. Виправляйте причину порушення замість вимкнення правила для всього проєкту.

## Backend, права та дані

- Webhook перевіряє секрет до розбору Telegram payload і передає команди у FIFO-чергу; бізнес-логіка виконується воркером.
- Зберігайте ідемпотентність за update ID, транзакційний запис результатів і receipt, повторну доставку та часткові помилки SQS batch. Не обіцяйте exactly-once доставку Telegram-повідомлень.
- TTL 30 днів стосується receipt команд. Заявки й історія змін не мають TTL; не додавайте їм строк автоматичного видалення без окремої вимоги.
- Створення заявки: будинок/комплекс → поверх (лише будинок) → категорія → опис, без окремого уточнення місця. Новим заявкам явно присвоюється `Public`; типове `Private` у моделі зберігається для безпечного читання старих payload. Не змінюйте видимість наявних заявок автоматично.
- Новий мешканець надає власний контакт Telegram, ім'я та прізвище; доступ активує адміністратор. Telegram ID — внутрішній ключ, його не потрібно показувати користувачам.
- Адміністратори зберігаються в окремій DynamoDB-таблиці `osbb-requests-<stage>-administrators`. Cognito-автентифікація сама по собі не надає доступу: сервер перевіряє `IsActive` та відповідну роль.
- **`IsSuperAdmin` редагується тільки людиною через AWS Console.** Не додавайте його запис до UI, API, Lambda, скриптів чи міграцій. Відсутність поля означає `false`; зберігайте захист IAM від його зміни.
- Лише активний супер адміністратор може надавати або відкликати доступ інших адміністраторів. Зберігайте серверні перевірки, optimistic concurrency та аудит адміністративних змін.
- Контакти, реєстрації й приватне листування не повинні потрапляти до публічних проєкцій заявок або журналів. Перевіряйте власника й комплекс під час доступу до даних.
- Використовуйте Query/GetItem та індекси у runtime-коді. Scan допустимий лише в окремих операторських сценаріях, як-от наявна міграція індексу.
- Секрети Telegram зберігаються в SSM SecureString; не виводьте їх, паролі або токени Cognito в логи чи відповіді.
- Дотримуйтеся `.editorconfig`, nullable annotations і наявного розділення handler/domain/persistence. Компіляторні попередження .NET трактуються як помилки.

## Перевірки

Запускайте перевірки, що відповідають зміненим частинам. Після успішних перевірок не повторюйте їх без нових змін або невирішених помилок.

Frontend:

```bash
npm ci --prefix src/Frontend
npm run check --prefix src/Frontend
npm run build --prefix src/Frontend
```

Для автоматичних виправлень: `npm run lint:fix --prefix src/Frontend`, потім `npm run format --prefix src/Frontend`. Для змін поведінки UI перевіряйте відповідні сценарії у браузері на desktop і mobile; використовуйте локальні тестові дані замість змін реальних мешканців.

Backend та операторські скрипти:

```bash
npm ci
dotnet restore OsbbRequests.sln --locked-mode
npm run build -- --no-restore
npm run test -- --no-build --no-restore
python3 -m unittest discover -s tests/admin -v
npm run check
```

Для змін пакування: `npm run package:dotnet`. CI виконує frontend-перевірки та збірку, backend-тести й форматування, Python-тести та ZIP-пакування. Автоматичного деплою в CI немає.

Додавайте тести для змін прав доступу, транзакцій, ідемпотентності та іншої бізнес-поведінки. Для документації або суто візуальних правок не створюйте тести, що лише повторюють реалізацію.

## AWS, Git і завершення роботи

- Stage за замовчуванням — `dev`, регіон — `eu-central-1`. Вказуйте stage явно в командах деплою та міграцій; працюйте в межах запитаного користувачем середовища.
- Один stage обслуговує один комплекс із чотирьох будинків і одного бота. Історичний `BUILDING_ID`/`BuildingId` є ID комплексу; не замінюйте його номером будинку. Заявки мають окремі `Scope`, `BuildingNumber` (рядок: `4Б`, `4В`, `4Г` або `4Д`) і `Floor` (1–25 або null). Не копіюйте конфігурацію або секрети між середовищами.
- Деплой інфраструктури: `npm run deploy -- --stage dev --region eu-central-1`; фронтенду: `python3 scripts/deploy-frontend.py --stage dev --region eu-central-1`. Деталі й міграції описані в README.
- Оновлюйте README й архітектурну документацію, коли змінюються поведінка, конфігурація або операторські процедури.
- Не перезаписуйте сторонні локальні зміни. Перед комітом перевіряйте `git status`, diff та `git diff --check`; додавайте лише файли відповідного завдання.
- Завершуючи роботу, стисло вкажіть результат, виконані перевірки, істотні обмеження та стан коміту/деплою. Не називайте незапущені перевірки успішними.
